## 3. 적용한 것 / 하지 않은 것

### 적용 ✅
| 변경 | 파일 | 근거 |
|---|---|---|
| `USE_TIMEOUT_EXIT: true → false` | `config.json` | 두 구간 모두 개선 |
| `PREFER_MAKER_ORDER: true` (+ post-only 진입 구현) | `config.json`, `core/config.py`, `core/exchange.py` | 두 구간 모두 개선 |

`_try_maker_entry()`는 최우선 호가에 post-only(GTX)를 걸고, 미체결·거부·예외 시 **시장가로 폴백**한다.
최악의 경우에도 현행과 동일하게 동작한다.

| 후보 | 이유 |
|---|---|

## 4. 남은 한계 — 반드시 읽을 것

1. **기저 전략에 지속적 엣지가 없다.** 이번 두 조치는 출혈을 줄일 뿐 수익을 만들지 못한다.
   후반 구간은 어떤 변형에서도 마이너스다.
2. **표본이 짧다.** 11일 · 4종목. 계절성·국면 다양성을 담기에 부족하다.
3. **메이커 체결률을 가정했다.** 백테스트는 100% 메이커 체결을 전제한다.
   실제로는 일부가 미체결→시장가 폴백이 되므로 이득은 이보다 작다.
   문헌도 "100% 패시브 체결 가정이 가짜 엣지를 만드는 가장 흔한 경로"라고 경고한다.
   → `[MAKER]` 로그로 실제 체결률을 측정한 뒤 재평가할 것.
4. **IP 밴이 상시 발생한다.** Binance 봇 4대가 한 IP를 공유한다.
   8408을 80→22종목으로 줄여 부하를 낮췄으나, 밴이 나면 신호 유실·주문 실패로 이어진다.
